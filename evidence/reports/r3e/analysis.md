## 结论：遗忘跟着“文件题写答案”的样本走，不跟着回放方式或推理走

五个版本放在一起：

| | 文件题写答案步骤在训练里 | 回放 | 迁移 |
|---|---|---|---|
| R3 | 有（无推理） | 无 | 1/36 |
| R3b | **删掉了** | 随机 | **15/36** |
| R3c | 删掉了 | LESS | 2/36 |
| R3d | 有（补写推理） | LESS | 6/36 |
| R3e | 有（补写推理） | 随机 | 1/36 |

- 只要文件族的“写出解答”步骤（约 300 条 `write_file`，多数原本无推理）留在训练里，迁移就塌；R3b 删掉它们，同类提升和遗忘一起消失。**提升和遗忘来自同一批样本。**
- 随机回放在 R3b 里“保住迁移”，其实是因为那一版根本没有学到会伤害迁移的东西，不是回放本身起的作用。R3e 用同一份随机回放，迁移照样 1/36。
- 推理不是原因：R3d/R3e 每次工具调用前都写推理，迁移仍塌。

## 迁移题到底怎么失败的（逐条看 v32 的模型轨迹）

- **写出来的代码本身变差**：例如 text_normalize 的 `slugify`，原学生用 `re.sub(r'[^a-z0-9]+', '_', …)` 并按字符过滤非 ASCII；R3e 用 `encode("ascii")`（遇到非 ASCII 直接抛错）、按 `"_"` 切分代替正则——两处都与要求不符。
- **写完不再检查**：写完后读回文件验证的比例，原学生 48/72（v26–v32 锚点合计），所有训练过的版本（R3、R3b、R3d、R3e）都是 0 或接近 0（R3b 第 1 轮 5/36）——训练轨迹在写完、检查器通过后就结束，学生学会了“写完即停”。原学生靠“写 → 读回 → 改”修好自己的第一版错误，训练后这条路没了。
- **“先读输入”不是区别**：R3 迁移题 36/36 都先读了输入，迁移照样 1/36。

所以遗忘是**写代码能力本身被这四族的解法覆盖**，加上**失去了写后验证的习惯**。回放用的 AgentNet（桌面操作文字）和 Toucan（MCP 工具调用）里没有写代码的样本，覆盖不到被伤害的能力——这与 R3c 的结论一致：回放要覆盖**被覆盖掉的那种能力**。

## 下一步（不再在这条线上继续迭代训练；记录为后续工作）
1. 回放改为“写代码”数据：最直接的是原学生自己在其它编程题上的成功解（自蒸馏回放，分布最贴近），或公开的代码指令数据。
2. 训练轨迹补上“写后读回验证”的步骤（或只保留带验证的轨迹），保住检查习惯。
3. 部署上：R3e 适配器在学过的族上最强（65/72），适合**按任务族路由**（门控只对学过的族启用适配器），而不是作为默认学生。
