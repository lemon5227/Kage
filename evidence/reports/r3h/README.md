# R3h：部署门控（离线合成，2026-10-31）

**问题**：R3 适配器在学过的题上大涨、在留出题上塌（`r3f-forgetting-fix.md`）。不训练，只在推理时按题决定加不加载适配器，能否同时拿到两边？

**做法**：门控就是 Kage 已有的相关性规则（`core/evolution/relevance.py`）：任务说明与适配器训练题（`evidence/reports/r2/sft-v21.jsonl.gz` 的 151 道题）的 TF-IDF 余弦最大值 ≥ 0.3 才加载适配器。路由只看任务说明文字，不看族标签和网页观察。
冻结评测每道题都在独立工作区里跑（只评 cp0，题与题之间没有记忆、技能或学习），所以门控运行逐题就等于“路由到适配器的题用适配器那次的结果，其余题用同会话原学生的结果”。用已有的同会话运行合成即可，不需要再跑模型：v26（R3 seed 0，适配器 3 次 / 原学生 3 次）、v32（R3e，3 / 1）、v41（seed 1、2，各 3 / 1）。统计方法同 `docs/paper/v0.5-support/verify.py`（题级、精确双侧 sign-flip、名义 p）。

```
python3 evidence/reports/r3h/analyze.py     # -> analysis.json
```

## 路由

| 题组 | 路由到适配器 | 最高相似度范围 |
|---|---|---|
| 文件·学过（4 族 24 题） | 24/24 | 0.895–0.98 |
| 文件·留出（2 族 12 题） | 0/12 | 0.123–0.165 |
| 文件·阴性（3 族 12 题，训练里有少量样本） | 7/12 | 0.225–1.0 |
| 网页·学过（3 族 18 题） | 18/18 | 0.853–1.0 |
| 网页·留出 web_form（6 题） | 0/6 | — |
| 网页·web_lookup（训练里 7 条样本，6 题） | 6/6 | — |

能力题零路由错误：学过与留出之间相似度差距很大（0.85 对 0.17），阈值在 0.2–0.85 之间任意取都不会错（阈值扫描见 `analysis.json`；0.1 时留出题全部误路由）。

## 结果

| 适配器 | 学过·文件 适配器 → 门控 | 留出·文件 原学生 / 适配器 / 门控 | 学过·网页 门控 | 阴性误用（门控） |
|---|---|---|---|---|
| R3 seed 0（v26） | 64/72 → 64/72 | 15/36 / 1/36 / **15/36** | 21/54 | 2/21 |
| R3e（v32） | 65/72 → 65/72 | 7/12 / 1/36 / **7/12** | 22/54 | 0/21 |
| R3 seed 1（v41） | 63/72 → 63/72 | 5/12 / 0/36 / **5/12** | 26/54 | 0/21 |
| R3 seed 2（v41） | 58/72 → 58/72 | 5/12 / 2/36 / **5/12** | 28/54 | 1/21 |

（v32、v41 的原学生只跑了 1 次，所以留出题门控结果按 /12 记。）

- 门控相对原学生：学过的文件题 +0.39…+0.47（p 从 11/32768 到 121/16384），学过的网页题 +0.20…+0.35；留出题与原学生**完全相同**（12 题全平）。
- 门控相对适配器：留出题 +0.36…+0.56（p = 1/64…1/16）。
- 误用只出现在被路由到适配器的阴性题上，与适配器单独运行时相同（seed 0 两次、seed 2 一次），门控既没有增加也没有消除。

## 结论与边界
- **部署层面，遗忘可以绕开**：只在学过的题型上加载适配器，就能保住全部提升，留出题退回原学生水平。代价是一次 TF-IDF 计算。
- **这不是修复**：适配器本身照样遗忘；门控对没学过的题型不提供任何提升（迁移为零是设计如此）。RSI 第二轮的进入条件要求一个模型同时满足“学过 ≥55/72、留出 ≥12/36、读回率 >0”，门控不满足，所以 R3g/R3f 仍要做。
- **路由零错误依赖模板化指令**：这些任务说明来自固定模板，同族相似度高、跨族低。自由表述的用户请求需要嵌入模型或学到的路由器，错误率要另测；本实验给出的是路由准确时的上限，以及阈值多宽时仍然正确。
- 合成依赖“题与题之间相互独立”：只评 cp0、没有记忆写入，满足这一点；若部署时开启记忆或技能学习，要实测。
