# D2：每日日程提醒 + 使用日志（2026-10-25）

## 读取日历：三条路，只有第三条可用
| 方式 | 结果 |
|---|---|
| Python 直接调 EventKit（pyobjc） | **静默拒绝**：请求立即返回 false、权限仍是“未决定”、不弹窗——Python 解释器没有用途说明（`NSCalendarsFullAccessUsageDescription`），macOS 不给它弹授权 |
| AppleScript 让“日历”应用读 | 用户点允许“控制日历”后可读；但**不展开重复日程**（每日站会只有首次） |
| **自带用途说明的小助手 `KageCalendar.app`**（`tools/kage-calendar`，Swift/EventKit，用 `open` 启动让权限归属它） | 正常弹窗、用户允许；重复/全天/跨天全部正确展开 |

## 验收（专用测试日历“Kage 测试”，iCloud，测完已删除）
5 个事件——全天（论文日）、普通（组会 @会议室A）、跨天（22:00–次日 01:00）、每日重复（10/22 起的站会）、带 15 分钟提醒（健身）——**5/5 读取正确**；当天恰逢欧洲夏令时结束（10-25 凌晨 3 点回拨），重复站会仍在本地 09:00。早报：今天视图标出已过/下一个/提醒，明天视图正确显示“（前一天开始）–01:00”；订阅的两个法国节假日日历重复的“冬令时”已去重。Kage 定时检查连跑 3 轮 → **早报只推送 1 次**（按日期去重 20 小时）。默认 12:30（用户选择），开启时心跳缩到 10 分钟。

“今天/明天有什么日程”走服务端直达（读日历，不经模型）。真实日程与待办只在本机显示，不进仓库。

## 使用日志（用户要求：记录用的时候干了啥，失败后记录用户怎么做到的）
`core/activity_log.py`：每轮（含直达通道）写 `~/.kage/activity/日期.jsonl` 并生成可读的 `日期.md`：请求、路径、每个工具成败、回复、状态（成功 / 失败 / **声称完成但没调用工具** / 闲聊 / 学到经验）。失败的回复末尾提示“告诉我‘我是这样做的：…’”；用户说了之后挂到那条失败记录下（`methods.jsonl`），并存进记忆（type=how_to，重要度 3），之后相似请求召回。“看看今天的使用日志”给出当天汇总。本机保存，不进仓库。
