# R3：LoRA-1 不带指导评测（Kaggle v26，2026-10-22）

**问题**：把 R2 里“带指导做成功、删掉指导”的 1900 条样本训练进权重后，学生**不带任何指导、记忆、规则**能不能把这些题做对？

## 设置
- 训练：Colab A100（用户的 Colab Pro），`r3-train`；1677 训练 / 223 验证（按族分层、按题划分），LoRA rank 16，lr 1e-4，2 轮 420 步，bf16 + flash-linear-attention，目标层 = 全注意力 `o_proj` + 全部 MLP（104 个模块，1894 万参数），上限 8192 token（0 条丢弃）。验证损失 0.2815（未训练）→ 0.1228 → 0.1155。配置与日志：`train-config.json`、`train-log.jsonl`、`data-stats.json`、`adapter_config.json`。
- 适配器：`adapter.gguf` sha256 `9f2713e9d318958e1434c70448272e9eab74de73f4cc204dcb4e9826b11a117a`（36 MB；存于用户 Google Drive `MyDrive/kage/` 与私有 Kaggle 数据集 `lemon5227/kage-r3-adapter`，不进仓库）。
- 评测：Kaggle v26 `r3-eval`，T4×2，同一会话里 L3（A0 + 适配器）与 A0 各 3 次，两套冻结评测集（`eval/stream_v1`、`eval/stream_web_v1`），全部 cp0、无老师；另加 30 题通用能力抽查（`general_check.py`）。原始结果 `evidence/kaggle/v26-results.tar.gz`，汇总 `summary.json`。
- **适配器确实生效**：同一题的第一次模型调用，A0 两次运行之间 28–29/48 完全相同（GPU 非确定性），L3 两次之间 45/48，L3 与 A0 之间仅 2–3/48；通用抽查中 L3 解码 30.3 ms/token vs A0 25.1。配置里记录了适配器 sha256。

## 解读

1. **巩固有效，而且不需要上下文**：文件学过的族 89%（64/72），高于 E-1 里带技能库 / 轨迹记忆的 81–88%，而 L3 评测时上下文里什么指导都没有。网页发票题 0 → 8/18：C2/C3 里“检索到却不照做”的规则（先展开全部行、按规则计算），现在进了权重。
2. **指导本来就无效的族，巩固也无效**：设置（4 vs 2）、酒店（9 vs 8）。与 R2 的对照（这两族带指导与不带一样）一致：R 环只能巩固“带指导能做对”的东西。设置题的瓶颈仍待 C4 判定（接口还是能力）。
3. **负结果：迁移族显著变差（15/36 → 1/36）**。原因找到了：L3 在**每一次**工具调用前都不再写推理（135/135 条说明为空；A0 为 10/157），训练数据里空说明只占 36%（522/1439）——SFT 把“直接动手”放大成了全部行为。学过的族里这是好事（直接做对），新族里少了“先列规则再写代码”就出错，例如 text_normalize 写出 `encode("ascii")`（不忽略非 ASCII，直接抛错）。
4. **负例略有误用**：`lookalike_readonly`（“已正确，不要修改”）两次被改。R2 数据里负例只占约 3%，与预期风险一致。
5. **通用能力未退步**：30 题逐字相同。适配器影响的是“工具使用的行为方式”，不是一般问答。

## 结论与下一步
- 论文 4.7：巩固把“带指导才会”变成“不带也会”，同类题大幅提升（p=2.6e-9 / 0.033），通用能力不变；**代价是新族迁移变差**——这是 SFT 窄化，与 Terminal-RSI 报告的跨基准提升不同，需要如实写。
- 不启用该适配器作为默认学生（迁移退步、负例误用增加）；在应用里只作为“已学任务的专用模式”候选。
- R4 之前先修数据：①只保留或加重带推理说明的目标（或在训练时对空说明降权）；②混入原学生自己做对的、无指导的样本（包括迁移族之外的通用工具使用）防止遗忘；③负例上采样；④更小学习率或 1 轮，对比迁移。迁移族仍永不进训练。
