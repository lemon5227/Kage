# D3：阅读邮件（只读，本地总结；2026-10-25）

**做法**：`core/mail_reader.py` 通过“邮件”应用的脚本接口（AppleScript）只读——未读列表（id、时间、发件人、主题、账户）、单封正文、收件箱未读数；从不标记已读、移动、删除或发送。“有什么新邮件 / check my new emails”列出最新 10 封；“读第 N 封”给正文；“总结第 N 封”交给**本地** 4B 模型总结（3 句以内：谁发的、要点、要不要我处理），邮件内容不出本机。中午早报附上未读数和最新 3 个主题。用户在首次弹窗允许“控制邮件”。

**测试**（真实邮箱，只读；内容只在本机核对，本文件只记统计）
| 项 | 结果 |
|---|---|
| 未读总数与“邮件”程序坞图标一致 | ✅（81，后为 63——用户期间读了邮件；三个账户收件箱 2 + 63 + 16 = 81） |
| 读取后邮件仍为未读 | ✅ |
| 10 封总结人工逐封对照原文 | **10/10 无事实错误**（日期、金额、型号、要做的事都对）；1 处措辞夹了未翻译的英文词 |
| 正文首次为空 | 邮件尚未下载，邮件应用按需拉取（26 s）→ 为空时等待后重读 |
| 端到端（Kage 后端 + 本地模型） | 列表 / 总结第 1 封 / 总结第 10 封 / 越界“第 11 封”提示 / 英文请求，全部正确；使用日志记为成功 |

**踩坑**
- 对统一收件箱用“未读”条件筛选得到 409 封，远多于未读数 81：脚本接口返回的“未读”集合与应用显示的未读数不一致，同一账户两次查询结果也不同（9 vs 7）。处理：总数用收件箱未读数（与用户看到的一致），列表按账户收件箱取最新的未读并按时间排序；作为已知限制记录。
- “总结第 1 封”含“总结”二字，被原有的“长任务转后台”规则截走（回复“先放到后台处理”）；桌面类直达请求（邮件、日程、使用日志）现在先于该规则判定为实时。
