# Kage 项目洞察与经验教训

> 面向面试与论文的“项目理解”汇总：每条都写清 **现象 → 证据 → 根因 → 怎么解决 → 现在状态 → 面试怎么讲**。
> 所有数字都有出处（括号里的文件），没有证据的不写。新的发现随时补进来（最后更新：2026-10-20）。

## 一页纸速览

**项目一句话**：一个跑在个人电脑上的 4B 本地智能体，在总共 $4 的云端老师预算下，从老师示范中学习电脑任务（写代码改文件、操作网页），会主动求教、空闲时自练，并在日常使用中积累数据。

**五个最值得讲的发现**

| # | 发现 | 一句话 |
|---|---|---|
| 1 | **检索到了却不照做** | 小模型拿到了正确的示范，却多数时候不照着做——瓶颈在“采纳”，不在“检索”（→ 第 1 条） |
| 2 | **自我修改会选中噪声** | 让 LLM 架构师改自己的策略，单次验证就晋级，结果选中了有害改动（→ 第 2 条） |
| 3 | **学到的东西会干扰陌生任务** | 没有相关性门控时，技能和示范会误导学生做没见过的题（→ 第 3 条） |
| 4 | **先量波动，再谈效果** | 温度 0 的同一个模型重复跑，48 题里有 15 题结果会变；学习方法之间的差距比这还小（→ 第 4 条） |
| 5 | **“通过”要逐题核对** | 校准时一类题 12/12 全过，逐题看动作才发现是网页缺陷让答案提前可见（→ 第 7 条） |

**核心结论**：从示范中学习非常有效（同类题从 29% 提到 81–94%，p≈6e-8），但学习方法之间、以及“主动性”“自我修改”这些更花哨的机制，在严格统计下都没有显著优势；小模型真正的瓶颈是“采纳指导”，所以下一步是把指导巩固进权重（巩固环）。

---

## 1. 检索到了却不照做（adoption gap）

- **现象**：浏览器任务上，学生每道评测题的提示里都带着相关的老师示范，但只有“操作字面一致”的题型有提升。
- **证据**（`evidence/reports/c2/analysis.md`，Kaggle v17）：发票题原学生三次重复都是 0/6，学习后 2、2、1、2/6；但发票示范大多以“Show more rows”开头，学生 6 题里只照做 1–2 次。通知设置题无提升（原学生 3/18），因为另一道题的点击序列带不出“只点状态不对的开关、只保存一次”这条规则；学生反而重复点同一项、保存两次。酒店题、表单迁移题都无提升。
- **根因**：①4B 模型对“前面对话里的示范”服从度低；②原始动作示范是**某一道题**的具体点击，真正可迁移的是规则，示范里没有。
- **怎么解决**：
  - C3：让老师对比“自己的成功步骤 vs 学生的失败步骤”，写 1–2 条不含具体数值的通用规则，按相关性注入提示（`core/evolution/lessons.py`），对照“只给规则”“示范 + 规则”（Kaggle v19 运行中）。
  - 巩固环 R（借鉴腾讯 Terminal-RSI）：学生带着指导在新变体上重做 → 只留验证通过的 → 删掉指导后训练 LoRA → **不带指导**评测。把“照着做”变成模型自己的能力（`docs/plans/rsr-consolidation-2026-10-18.md`）。
- **状态**：C3 运行中；R1（泄漏筛查）、R2（采集）已实现，待 Kaggle 跑。
- **面试怎么讲**：“我们以为难点是让模型找到相关经验，结果检索 100% 命中，但小模型就是不照做。这改变了研究方向：与其继续优化检索，不如把带指导时的成功训练进权重。这也是我们和谷歌 Harness²（只改外层、默认模型会照做）的关键区别——外层改进的前提在小模型上不成立。”
- **可能的追问**：“怎么知道是不照做而不是检索错了？”——逐题看了第一条提示里有没有示范（全部有）和学生实际动作（标签级记录，`acted` 字段）。

## 2. 自我修改会选中噪声（L2 架构师）

- **现象**：让 LLM 架构师（参考 Meta-Harness）改写“选用哪个技能”的策略，验证通过才晋级。结果有害改动被晋级，带架构师的一组反而更差。
- **证据**（`docs/report/kage-tech-report.md` §5.4，E-2/E-2b）：架构师 6 轮都给了提案，2 个被晋级，晋级理由都是“约 10 道验证题里有 1 道变好、没有变差”；其中一个把相似度阈值从 0.3 降到 0.1，等于撤掉了相关性门控。A6（有架构师）41/48，A6-fixed（固定规则）45/48；留出集 9/24 vs 12/24。
- **根因**：学生本身有随机性（第 4 条），10 道题、每题只跑一次的验证，“1 道变好”完全在噪声范围内。晋级规则没有考虑方差。还有一个工程原因：E-2 第一次跑时架构师不知道自己的轮数上限，8 轮全用来读文件，一次也没提案（加了轮数提示后修好）。
- **怎么解决**：晋级必须用每题多次重复、并包含陌生题型的验证；借鉴谷歌 Harness²：在同样条件下成对试跑候选与现行策略，按行为证据而不是一次分数决定（已列入 roadmap 待办，排在巩固环之后）。
- **状态**：负结果已写入技术报告；改进方案在待办。
- **面试怎么讲**：“自我修改最大的风险不是改不出东西，而是评估太弱时会自信地选中噪声。这个负结果让我们把‘先量方差’变成了所有实验的规矩。”

## 3. 学到的东西会干扰陌生任务 → 相关性门控

- **现象**：没有门控时，学生在没学过的题型上也会看到无关的技能和示范，表现被拖到原学生之下。
- **证据**（技术报告 §5.3–5.4）：无门控的 A4m 留出集 9/24，且出现 1 次负例误用；加门控后，48 道留出题上一次都没注入技能或示范，留出分数回到原学生的范围（约 6/12，原学生 5–8/12），负例零误用；同类题上门控从未挡掉该给的技能。
- **根因**：最初用 Jaccard 词重合度判断相关性，不同题型之间分不开（0.17–0.24，阈值 0.2）。
- **怎么解决**：TF-IDF 余弦相似度，文档频率只来自智能体自己见过的指令（不用基准标签）；门控全空时，提示与原学生逐字节相同（`core/evolution/relevance.py`）。智能体自己的聚类纯度 100%。
- **面试怎么讲**：“记忆越多越好是错觉。我们把‘不相关就什么都不给，和没学过时一模一样’作为硬约束，并用‘提示逐字节相同’来测试它。”

## 4. 先量波动，再谈效果（GPU 非确定性）

- **现象**：同一个模型、温度 0、单槽服务，重复评测结果不一样。
- **证据**（技术报告 §5.4）：四次相同的原学生评测，48 题里 15 题结果变化，全部不是超时；同类题 7、10、13、7/24。
- **根因**：llama.cpp 在 GPU 上的计算不是逐位可复现的（并行规约的浮点顺序不同）。
- **一个必须坦白的错误**：我们一度在日志里写“学生用温度 0.7 采样”，这是错的——查代码发现强制温度 0。已更正技术报告，并记录更正过程。
- **怎么解决**：原学生每次实验都跑 3 次以上给出波动范围；配对检验（McNemar）只在同类题上做；把“学习 vs 不学习”（差距约 45 个百分点，远超波动）和“学习方法之间”（差距小于波动）分开下结论。
- **面试怎么讲**：“温度 0 不等于确定性。我们在比较方法之前，先测了系统本身的噪声；很多看起来的‘提升’在这个噪声面前不成立。”

## 5. 技能库并不比轨迹记忆强

- **证据**（技术报告 §5.2，E-1）：技能库 A4 81% vs 轨迹记忆 A3 88%，配对 5:8，p=0.58。按 M3 停止条件，先诊断再扩展。
- **根因（诊断出两个）**：①技能预览按字母排序，库变大后把匹配的技能挤出了预览（同类题 8 个失败全是这个原因）；②技能只在来源那一道题上验证就入库，导致技能太窄。
- **怎么解决**：按相关性排序预览（A4r）；入库前在同族最近几道题上验证、失败就要求老师改写成通用版本（A4g）；技能 + 记忆（A4m）43/48。仍与记忆不显著不同——如实报告。
- **面试怎么讲**：“结构化的技能听起来比原始轨迹高级，但在这个规模上没赢。诊断出的是‘工程细节决定成败’：预览排序这种小事能让技能完全失效。”

## 6. 主动求教几乎不触发

- **证据**：A5 在 120 个流任务里只有 1 次“先问再做”（技术报告 §5.4）。
- **根因**：在一个新题型上第一次失败后，失败后求教就已经教会了相关的东西，之后策略改为“先自己试”，“能力低且没有相关知识”的状态很少持续。
- **结论**：这个机制在这个基准上没有发挥空间——是“未被检验”，不是“被证伪”。这种区分在面试里很重要。

## 7. 基准设计：难度从哪来，以及“通过”要逐题核对

- **难度**（`evidence/kaggle/v13–v16-c-cal-summary.json`）：动作 ≤4 的单页任务，即使值要从页面读、要按规则算，4B 学生也 92–100% 做对；真正难的是**长流程 + 需要主动揭示的信息**（隐藏行要先展开、评分要点开才显示）。四轮校准后才落到目标区间。
- **三个差点让结果作废的坑**：
  - 网页样式 `label{display:block}` 覆盖了 `hidden`，两步表单的第二步字段一开始就可见——表单题 12/12 全过是假的。逐题看动作发现“从没点过 Next 也全过”才查出来。
  - 点完保存马上结束时，保存结果来不及显示，正确的任务会随机判失败——加了最多 1 秒的保存确认。
  - 题目措辞各写各的、又带大量独有取值，同类题相似度只有 0.05–0.17，记忆根本检索不到——统一同类题的核心措辞后提到 0.41–0.83。中文句式与英文不共享词，会把一类题拆成两组，所以基准只用英文。
- **面试怎么讲**：“我不相信只看分数的结果。每次分数异常（太高或太低）都逐题看动作，三次都查出了真问题。”

## 8. 数据纪律：泄漏与隐私

- 老师重做原来按自己的 id 划分训练/留出，会把留出任务的做法带进训练集 → 改为继承原任务的划分。
- 老师写的规则可能含当前题的答案 → R1 泄漏筛查（`core/evolution/leakage.py`）；它最初把 `ERROR`、`email` 这类普通词也当泄漏，验收时发现并修正。
- 迁移测试用的题型（F5/F6、表单）和评测种子永远不进训练（代码里硬性拒绝）。
- 真实使用数据只存本机、可删可关；只有脱敏导出才可能用于训练；约 1/10 真实任务留作评测。

## 9. 实验基础设施的教训（Kaggle 免费 GPU）

详见 `docs/development/kaggle-runbook.md`（13 条）。最有代表性的：
- 服务崩溃后的题被记成“学生失败”，分数全错 → 崩溃不是能力结果，单独抛异常、自动重启并按题续跑。
- 预算被拒的结果被缓存成“示范” → 预算拒绝必须停止学习、绝不缓存。
- 四台模型服务各占 8GB 主机内存缓存 → 被系统杀掉，`--cache-ram 0` 解决。
- 命令行启动的运行读不到 Secrets → 正式运行一律从网页启动。

## 10. AI 协作开发：Claude 规划验收，DeepSeek 执行

- 分工：Claude 写任务卡、审查每处改动、自己重跑测试；定义清楚的实现交给 DeepSeek-V4.1-Flash 执行器（独立 Claude Code 进程，公开仓库 github.com/lemon5227/deepseek-agent）。
- 经验：代码质量约 8/10，会主动发现任务卡没写到的问题；但**自述不可全信**（一次说临时文件在仓库外，实际在仓库内），所以测试必须自己重跑；任务卡没写清的错误处理就会出 bug（预算耗尽时崩溃而不是停止）。
- 安全：用假服务器核实子进程只发送 DeepSeek 的 key、不发送 Claude 登录凭据；护栏钩子在每次工具调用前硬拦截，但承认它是安全网不是沙箱。
- 成本：一次中等功能（R2，424 行 + 测试）约 ¥0.9，返工一次约 ¥0.01。

## 11. 与同期工作的关系

- **腾讯 Terminal-RSI**（arXiv:2610.22192）：改权重——带 runbook 重做 → 删指导做 SFT → 强化学习，27B。我们的巩固环借鉴了它的 RSR 部分，不做 PPO（T4 + 4B 做不了），用多次采样只留成功代替。
- **谷歌 Harness²**（arXiv:2610.14224）：改外层——提示/技能/记忆等，同条件试跑对比、不需要标准答案，强模型上有效。
- **我们的位置**：两层都做，在 4B + $4 的极端约束下；并且有它们都没有的证据——外层改进的前提（模型会照做）在小模型上不成立。时间上是同期独立工作（git 时间戳可查）。

## 面试常见追问与回答思路

- **“项目最大的挑战是什么？”** → 第 1 条（不照做）或第 4 条（噪声）。讲“我们以为问题在 A，证据说问题在 B，于是改了方向”。
- **“有什么失败的地方？”** → 第 2 条（L2 选中噪声）、第 5 条（技能不比记忆强）、第 6 条（主动求教没触发）。负结果要讲成“学到了什么、怎么改规矩”。
- **“怎么证明你的方法有效？”** → 冻结的基准（哈希）、原学生三次重复给出波动范围、同类题配对检验、留出题型测迁移、负例测误用；每个数字都在 `evidence/` 里能复算。
- **“如果重来会怎么做？”** → 一开始就测系统噪声；一开始就把基准难度来源想清楚（长流程而非单步）；更早做逐题动作诊断。
- **“成本？”** → 老师总预算 $4，到目前约用 $1.6；实验全跑在 Kaggle 免费 T4；开发执行器约 $0.65。
- **“和大厂的工作比有什么价值？”** → 第 11 条：同一问题在极端资源约束下的答案，以及“小模型不照做”这个它们没有的发现。
