# W1-8 难度标定脚本

- 档位：低（写脚本）/ U（运行）　依赖：W1-2…W1-7 ✅
- 先读：`scripts/experiments/stream_run.py`（复制它的 llama-server 管理与 `chain_runner` 用法）、`core/evolution/stream_tasks.py`
- 产出：`scripts/experiments/stream_calibrate.py`、`tests/test_stream_calibrate.py`

## 脚本行为
```
$PY scripts/experiments/stream_calibrate.py --root artifacts/stream-calibration [--per-family 10] [--families a,b,...] [--no-manage-server]
```
1. 对每个能力族（`FAMILIES` 里不在 `NEGATIVE_FAMILIES` 的）用 seed `5000 + i`（i = 0..per-family-1，必须落在 calibration 区间）生成任务；负例族同样各跑 per-family 个。
2. 用空技能库（与 stream_run 相同的 bootstrap）跑 A0 学生：`chain_runner(journal, local_budget, root/'workspaces', student_model, skill_runner=docker)`。不调用任何云模型。
3. 每跑完一个任务追加一行到 `root/results.jsonl`：`{family, seed, score, status, seconds}`；已有记录的 (family, seed) 跳过（可续跑）。
4. 结束时打印并写 `root/summary.json`：每族 `passed/total`、成功率、是否在 [0.10, 0.50] 区间（负例族显示通过率，不做区间判定）。

## 测试（沙箱，不需要模型）
把「跑一个任务」的函数做成参数注入，测试里用假函数：
- 续跑：已有 results.jsonl 里的条目不会再跑
- summary 的区间判定正确
- 所有 seed 都在 calibration 区间（`split_of(seed) == 'calibration'`）

## 运行（U）
预计 7 类 × 10 = 70 次，每次 30–75 秒，约 1 小时，零云费。

## 完成判定
测试通过；用户跑完后日志记录每族成功率；区间外的族在 W1-9 前调整参数（调整方法：改生成器里随机范围，比如更多物品、更多畸形行；改完重跑这一族的标定）。
