# W2-3 A1 等预算重试臂

- 档位：中　执行者：C 或中档模型　依赖：W2-1 ✅
- 先读：`core/evolution/retries.py`（`LocalRetryProvider`）、`core/evolution/stream.py`（`ARMS`、`chain_runner`）、`scripts/experiments/learning_ablation.py` 第 95–100 行（retries 臂怎么构造）
- 产出：`core/evolution/stream.py`（`ARMS['A1']`、`retry_runner(...)`）、`stream_run.py`（A1 用 retry_runner）、测试 `tests/test_stream_retry_arm.py`

## 做法
1. `ARMS['A1'] = {'learn': False, 'help': 'never'}`。
2. 新函数 `retry_runner(journal, budget, workspaces, model_factory, *, skill_runner=None, max_model_calls=6, max_steps=5, ...)`，返回同样签名的 `run(candidate, task, run_id)`。内部：`LocalRetryProvider(factory, task, max_model_calls, max_steps)`，其中 `factory(call_cap, step_cap)` 构造一个 `KageChainProvider`（`max_model_calls=call_cap`，`agentic_loop_cls` 的 `MAX_STEPS=step_cap`）。总请求数和总步数上限与 A0 完全相同。
3. `LocalRetryProvider` 每次重试之间会用 `Evaluator.score` 判断是否已通过——这相当于环境告诉它「还没对」，和 A4 用任务结束后的反馈是同一类信号，可以接受；在日志和报告里写明。
4. stream_run：`--arm A1` 时用 `retry_runner` 代替 `chain_runner`。

## 测试
用 `tests/test_stream_chain_integration.py` 里的脚本化模型思路：第一次尝试不写文件、第二次写正确文件的假模型 → A1 在同一任务上得 1 分，且总模型调用 ≤ 6。
