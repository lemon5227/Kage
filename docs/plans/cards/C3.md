# C3: teacher-written lessons for browser tasks (rule vs raw demonstration)

Executor: DeepSeek Harness (dsh). Reviewer: Claude. Read this whole card before changing anything.

## Why

C2 (Kaggle v17, `evidence/reports/c2/analysis.md`) showed: on browser tasks the student always
retrieves the remembered teacher demonstration, but rarely follows it, and a raw click list from
another instance does not carry the rule that matters (e.g. "only click checkboxes whose current
state differs from the target, save once"). C3 adds teacher-written lessons (one-line transferable
rules) and compares "rule only" and "demo + rule" against v17's arms on the same frozen benchmark.

## What to build

### 1. `core/evolution/lessons.py` (new)
- `LESSON_PROMPT`: asks the teacher, given (a) the task instruction, (b) the teacher's successful
  label-level steps, (c) the student's failed label-level steps, for 1-2 lessons that would make a
  small model succeed on OTHER tasks of the same kind. Lessons must be generic: no instance values
  (no names, numbers, emails, hotel names, totals). Reply format: only JSON
  `{"lessons": [{"when": "...", "do": "...", "avoid": "..."}]}`.
- Steps come from `core.evolution.stream._browser_rows(result)` (already exists; it yields
  `{'action': {'name','arguments': {'operation','target','value'?}}, ...}`). Render each as one line,
  e.g. `click "Show more rows"`, `fill "Total" = "1143"`.
- `extract_lessons(model, budget, *, task, demo, student, run_id) -> list[dict]`:
  - builds the prompt; the whole request must stay under `MAX_INPUT_BYTES = 24000` bytes (truncate
    the step lists, never the instruction);
  - reserves the call in `budget` before calling and settles it afterwards with the reported usage,
    exactly the way `core/evolution/mutator.py` does (read it; use `call_type='lesson'`);
    a `BudgetExhaustedError` must propagate (the caller stops learning), other model errors -> `[]`;
  - calls `model.generate(messages=[...], max_tokens=600, temperature=0.0)`;
  - parses the JSON (tolerate ```json fences and leading text), passes it through
    `core.evolution.playbook.parse_lessons({'lessons': [...]})` after setting `'scope': 'task'` on
    every item (browser lessons are always task-scoped), returns the list (max 2);
  - never puts `task['scoring_criteria']` or anything from it into the prompt.

### 2. `core/evolution/playbook.py`
- `Playbook.add(...)`: also store `'triggers'`: up to the last 5 raw instructions (each <=400 chars)
  that produced/merged the entry (keep the existing `trigger` word field unchanged).
- `Playbook.select(instruction, similarity=None, min_score=0.0)`: when `similarity` is given,
  task-scoped entries are scored by `max(similarity(instruction, t) for t in entry['triggers'])`
  and kept only if `>= min_score` (top `TASK_TOP_K` by score); general entries behave as before.
  Without `similarity` the behaviour must be exactly the current one (existing tests stay green).
  Old entries without `triggers` are skipped when `similarity` is given.

### 3. Browser chain uses guidance
- `core/computer_use/experiment.py`: `BrowserChainProvider._experiment_soul()` appends
  `'\n' + self.extra_guidance` when `self.extra_guidance` is non-empty (the attribute already exists
  on the parent `KageChainProvider`). Empty guidance -> the soul is byte-identical to today.
- `core/evolution/stream.py` `chain_runner(...)`: new keyword args `playbook_similarity=None,
  playbook_min=0.0`. In `browser_chain`, when `playbook` is set: `lessons = playbook.select(
  task['instruction'], similarity=playbook_similarity, min_score=playbook_min)`, pass
  `extra_guidance=playbook.render(lessons)` to the provider (student only, not when `cloud=True`),
  and after the run call `playbook.record_use(lessons, result.score >= 1.0)` + `playbook.save()`
  when lessons were shown (same as the file-task path does). The file-task path should pass the
  same similarity/min to `select` too.

### 4. Arms and learner (`core/evolution/stream.py`)
- New arms:
  - `'A4mGL'`: same as `'A4mG'` plus `'lessons': True` (demo memory + lessons).
  - `'AGL'`: `{'learn': 'lessons', 'help': 'after_failure', 'gate': True, 'clusters': True, 'lessons': True}`
    (lessons only, no demo memory, no skills).
- `StreamLearner.__init__`: new optional params `playbook=None, extract_lessons=None`
  (`extract_lessons(task, demo, student) -> list[dict]`). Arms with `'lessons'` require both
  (raise `ValueError` otherwise, like the other checks). `learn == 'lessons'` needs a teacher but no
  memory store and no skill proposer.
- `_learn`: when `learn == 'lessons'`, do not touch memory or skills; return
  `{'attempted': True, 'accepted': False, 'kind': 'lessons'}`.
- `step`: right after `_learn` for a task with a verified demo (same condition as today:
  `demo.score >= 1.0 and changed_state(task, demo)`), if the arm has `'lessons'`: call
  `extract_lessons(task, demo, student)` (`student` may be `None` when help was asked first),
  `playbook.add(lessons, source_task=task['task_id'], family=task['family'], trigger=task['instruction'])`,
  `playbook.save()`, and record `row['learning']['lessons'] = {'n': len(lessons), 'outcomes': [...]}`.
  If lessons were added, set `row['learning']['accepted'] = True` (so `record_help_outcome` counts the
  help as learned). Lessons are learned for browser tasks only (`task.get('fixture') is not None`).

## Tests (new file `tests/test_stream_lessons.py`; use scripted models, no network)
1. `extract_lessons`: fake model returning fenced JSON -> parsed, scope forced to `task`, at most 2;
   garbage reply -> `[]`; the prompt contains the instruction and both step lists and does NOT
   contain any value from `scoring_criteria`; request bytes <= 24000 even with very long step lists;
   a `BudgetTracker` on a temp path shows one reserved+settled call.
2. `Playbook.select` with a similarity function: a same-kind instruction gets the lesson, an
   unrelated one gets nothing; without similarity the old behaviour is unchanged.
3. `BrowserChainProvider` soul: identical with empty guidance, contains the guidance text otherwise.
4. Learner + real chain (model it on `test_gated_learner_learns_a_browser_procedure_from_the_teacher`
   in `tests/test_stream_browser.py`, reuse its helpers by importing from that module): arm `AGL` on
   two `web_invoice` tasks with a scripted extractor returning
   `[{'when':'an invoice table has hidden rows','do':'click "Show more rows" before computing','avoid':''}]`;
   the student model reveals rows only if the system prompt contains `Show more rows` in a lessons
   block. Assert: first step student fails, teacher passes, lessons stored, no `memory.jsonl` lines;
   second step solved by the student without help.
5. Gating end to end: after a lesson from `web_invoice`, a `web_prefs` task's student prompt has no
   lessons block (record prompts through a file: the chain runs in a forked worker).
