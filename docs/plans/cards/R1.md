# R1: leak screen for lessons/runbooks and guidance-free training samples

Executor: DeepSeek executor. Reviewer: Claude. Read the whole card first. Plan context:
`docs/plans/rsr-consolidation-2026-10-18.md` (R1).

## Why
Lessons (C3) will become runbooks for guided practice (R2), and guided successes become training
data with the guidance removed. A lesson that contains an instance's answer or instance-specific data
would teach the answer instead of the procedure, and a training sample that still contains guidance
would teach the model to expect it. Both must be caught deterministically, before storage/training.

## Build `core/evolution/leakage.py` (new)
1. `instance_values(task: dict) -> set[str]` — values that belong to THIS instance (never generic UI words):
   - browser tasks (`task['fixture']` present): every value in `scoring_criteria['expected']['record']`
     (stringify numbers/bools are NOT included when they are booleans), fixture text-field `initial`
     values, invoice row `item` names and `qty`/`price` numbers, catalog item `name`/`city`/`id`,
     contact-note lines' values (the text after `": "` in each `fixture['note']` line, skip the first
     line "Contact note");
   - file tasks (`scoring_criteria['type'] == 'python_function'`): `scoring_criteria['function']`,
     `scoring_criteria['file']`, and every string (len >= 4) and number (abs >= 10) found anywhere
     inside `scoring_criteria['cases']` (recurse through lists/dicts);
   - all tasks: quoted substrings in `task['instruction']` (`"..."` or `'...'`, len >= 3) and numbers
     with at least 2 digits in the instruction.
   - Exclude generic words: field/button labels from the fixture (`label`, `submit`, `query_label`,
     `category_label`, `apply_label`), and anything shorter than 2 characters.
   Numbers are compared as text: `1143` matches `1143` and `1,143`.
2. `leaks(text: str, task: dict) -> list[str]`: the instance values found in `text`, case-insensitive,
   matched on word boundaries for alphanumeric values (so `12` does not match inside `2012`).
3. `screen_lessons(lessons: list[dict], task: dict) -> tuple[list[dict], list[dict]]`: (kept, rejected),
   checking `when`/`do`/`avoid` of each lesson; rejected items get `'leaked': [...]`.
4. `guidance_free(messages: list[dict], guidance: list[str]) -> bool`: True when no message content
   contains any guidance text (compare each guidance string's lines of length >= 20 chars,
   whitespace-normalized) — used by R2 before writing a training sample.

## Wire it in `core/evolution/stream.py`
In `StreamLearner.step`, where lessons are extracted for browser tasks: run `screen_lessons` on the
extracted lessons before `playbook.add`; only kept lessons are added; record
`row['learning']['lessons'] = {'n': len(kept), 'rejected': len(rejected), 'outcomes': [...]}`
(keep `'n'` meaning "added candidates" so existing tests still pass; adjust only if a test needs the
new key). Keep the existing `TeacherBudgetExhausted` handling exactly as it is.
