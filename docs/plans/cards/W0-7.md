# W0-7 一次性安装 Mac 推送代理（替代手动推送 W0-3）

- 档位：低　执行者：U（只需一次）　依赖：无
- 目的：Claude 和便宜模型运行在沙箱里，没有 GitHub 凭据；Codex 能推是因为它直接跑在 macOS 上。推送代理让沙箱里的模型**提出推送请求**，由 Mac 上的 launchd 用你自己的凭据执行。凭据不离开 Mac，也不交给任何模型。
- 产出：`scripts/dev/push_agent.sh`、`scripts/dev/com.kage.pushagent.plist`、`scripts/dev/request_push.py`（已写好、已在假仓库测过）；队列目录 `.kage-push/`（已加入 .gitignore）。

## 安全边界
- 只推 `.kage-push/allowed.txt` 里匹配的分支，默认 `evidence/*` 和 `claude/*`。**main 默认不允许**；想允许就自己往 allowed.txt 加一行 `main`。
- 只执行 `git push origin <分支>`，不带 `--force`，不执行请求里的任何其他内容；分支名只允许字母、数字和 `._/-`。
- 每次推送记录在 `.kage-push/agent.log` 和 `.kage-push/results/`。

## 安装（一次）
```sh
cd /Users/wenbo/Kage
mkdir -p .kage-push
cp scripts/dev/com.kage.pushagent.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.kage.pushagent.plist
sleep 5; cat .kage-push/agent.log
```
已经排队了一个请求：推送 `evidence/2026-10-14`。安装后 1 分钟内 agent.log 里应出现 `... evidence/2026-10-14 pushed`。如果显示 `failed`，看 `.kage-push/results/*.json` 的 detail；通常是本机 git 凭据问题，在终端里手动 `git push origin evidence/2026-10-14` 一次，让钥匙串记住凭据即可。

## 卸载
`launchctl unload ~/Library/LaunchAgents/com.kage.pushagent.plist && rm ~/Library/LaunchAgents/com.kage.pushagent.plist`

## 模型怎么用
`python scripts/dev/request_push.py claude/W1-2 --wait`（最多等 5 分钟，打印结果）。

## 完成判定
GitHub 上能看到 `evidence/2026-10-14`；日志记录推送结果。
