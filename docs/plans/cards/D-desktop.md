# D 阶段：日常桌面助手（2026-10-24 起）

**目标**：把 G0 的研究成果变成用户每天会用的能力。用户最常用的四件事：**每日日程提醒、阅读邮件、打开软件、微信操作**。
**原则（用户 10-24）**：能用命令行/脚本接口就用，不能用才模拟界面操作。层级：
1. 命令行（`open`、`defaults`、`mdfind`、`shortcuts`、文件工具）；
2. 应用脚本接口（AppleScript/JXA 或系统框架），**做成现成技能**，不让 4B 模型自己写脚本；
3. 辅助功能接口（G0 驱动）——默认只读，写操作要用户确认；也用来“定位”（如读出打开文档的真实路径），再交给命令行动手；
4. 截图 + 文字识别 / 视觉模型——前三层都不行时。
网站：优先 OpenCLI（`jackwener/opencli`，把网站变成 JSON 命令，用已登录的 Chrome；默认只开读取类命令，写操作确认；安装需用户同意，扩展由用户装）。

**10-24 现状调查**（本机）
- 打开软件：已有 `open_app`。
- 邮件：用户用系统“邮件”应用（4 个账户），有脚本接口。
- 日历：系统“日历”，有脚本接口 / EventKit；首次访问需用户授权（隐私设置，用户点）。
- 微信 4.1.13：辅助功能树只有 6 个节点，`AXManualAccessibility`/`AXEnhancedUserInterface` 设置被拒（-25205/-25208）→ 辅助功能接口不可用；只能截图 + 文字识别读、模拟键盘发（每条确认）。
- Kage 应用已接入 `desktop_task`/`desktop_learn`（10-24）：系统设置读取实测正确；TextEdit 失败（模型没给文档名、`exec` 编造路径 `/Users/yourname/...`）——正是缺“定位”这一步。

## 任务

| ID | 任务 | 做法 | 验收 | 依赖 / 用户动作 |
|---|---|---|---|---|
| **D0** | 命令行优先的工具规则 + 文档定位 | 工具说明与可见性按层级重写；新增 `open_documents`（辅助功能读各应用窗口的 `AXDocument` → 真实路径），改文件走文件工具；系统设置能 `defaults read` 的先用命令；计算器从应用里移除（只留实验/演示） | 端到端：“把 TextEdit 里打开的 X 文档的错字改掉”用文件工具完成，路径正确；10 条“改/读打开文档”请求 ≥ 9 次走命令行且成功 | — |
| **D1** | 打开软件 | 应用名解析：`mdfind kMDItemKind==Application` + 中英文名/别名表（微信=WeChat、飞书=Lark…）；`open -a` | 20 条常见说法（中英文、简称）打开正确应用 ≥ 19/20 | — |
| **D2** | 每日日程提醒 | 技能 `calendar_events(day)`（EventKit，只读）；主动提醒源：每天设定时间（默认 8:30）推送“今天的日程 + 提醒事项”，接入现有 heartbeat/通知；用户可改时间、关掉 | 在专用测试日历里放 5 个事件（全天/跨天/重复/提醒）读取 5/5 正确；早报按时出现一次、不重复 | 用户授权日历访问；建测试日历需用户同意 |
| **D3** | 阅读邮件 | 技能 `mail_unread(limit)`、`mail_read(message)`（AppleScript 驱动“邮件”应用，只读）；本地模型总结；可并入早报 | 未读数与“邮件”应用一致；10 封总结人工抽查无事实错误；邮件内容不出本机（云端总结需用户另行允许） | 用户在首次弹窗里允许控制“邮件” |
| **D4a** | 微信：可行性验证（只读） | 截图微信窗口 → macOS Vision 文字识别（本地、中文）→ 会话列表、未读、最近消息结构化 | 10 张截图：会话名与未读数准确率 ≥ 90%；给出“做 / 不做”的结论 | 已有录屏权限 |
| **D4b** | 微信：发消息（D4a 通过才做） | 找到会话 → 粘贴文本 → 回车；**每条消息先给用户看并确认** | 测试会话（用户的文件传输助手）10/10 发对，零误发 | 用户确认每条 |
| **D5** | OpenCLI 接入（网站） | 安装 + Kage 工具 `opencli`（只读命令白名单，写命令确认） | B 站 / 知乎 / 小红书各 3 条读取请求成功 | 用户同意安装、装 Chrome 扩展 |
| **D6** | 演示视频 + 论文定稿 + README | 录：早报 → 读邮件 → 打开软件 →（微信只读）；论文补图与参考文献、挂 arXiv；README 更新；合并 main | 视频 ≤ 3 分钟；arXiv 链接写进简历 | 合并需用户同意 |

**顺序**：D0 → D1 → D2 → D3 →（D4a、D5 并行）→ D4b → D6。每项做完写工作日志与证据（`evidence/reports/d*/`），真实邮件/日程/聊天内容**不进仓库**（只存统计与脱敏样例，见 memory usage-data-local-only）。
