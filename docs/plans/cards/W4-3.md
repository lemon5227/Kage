# W4-3 云端架构师（Meta-Harness 式）

- 档位：高　执行者：C（强模型）　依赖：W4-4
- 先读：Meta-Harness 论文摘要（arXiv 2603.28052）、`core/evolution/recovery_mutator.py`（现有的 12KB 压缩反馈写法，这次要反过来）、`core/evolution/bundle.py`
- 产出：`core/evolution/architect.py`、`tests/test_architect.py`

## 可演化对象（只这 4 个，以 bundle 模块形式存在）
`prompt_template`（学生系统提示的附加段）、`skill_selection`（给定指令和技能描述返回要预览哪些技能）、`help_policy`（W3-2 的 recover 函数）、`recovery`。评分器、预算、回退、执行内核**冻结**，架构师不可见其写权限。

## 工作方式
1. 架构师（DeepSeek）拿到：任务说明 + 一个只读工具集 `ls(path)`、`cat(path, start, end)`、`grep(pattern, path)`，根目录是「版本档案」：每个版本的源码、验证分数、每个验证任务的原始轨迹（去掉 scoring_criteria）。
2. 多轮工具调用（上限 8 轮），最后输出 JSON：`{target, hypothesis, code}`。
3. 候选在 validation 集（eval 区间之外另划 `validation: range(17000, 19000)`）上与父版本同预算比较；不退化且至少一题改善才晋级；用 RecoveryLoop 已有的 active/回退机制保存。
4. 每个候选费用 ≤ $0.015（先在账本预留），超出即停。

## 测试（脚本化架构师）
只读工具不能越出档案根目录；不能看到 scoring_criteria；非法 target 被拒；晋级与拒绝两条路径；费用预留先于调用。
