## Idea (Terminal-RSI's RSR, adapted)
The local student re-solves FRESH task variants with guidance in its prompt (a remembered teacher
demonstration and/or teacher-written lessons). Only strictly verified successes are kept. The guidance is
then removed from every recorded model call, so a training sample looks exactly like the raw student's
(A0) request with the student's own successful response as the target.

## 1. Temperature for the student client
`scripts/experiments/task_suite.py` `RecordedLocalProvider.generate` forces `temperature = 0`.
Add an optional constructor argument `temperature=None`; when it is not None use it, otherwise keep 0.
Default behaviour must not change (all existing experiments rely on it).

## 2. `scripts/experiments/rsr_collect.py` (new)
Commands:
- `collect --root DIR --port P --families a,b,... --seeds N --k K --temperature T
   --memory FILE [--memory FILE ...] [--playbook FILE ...] --guidance demo|lessons|both
   [--negatives M] [--skill-runner process] [--no-manage-server]`
- `build --root DIR` (writes `DIR/sft.jsonl` and `DIR/stats.json`; no model needed)

Rules for `collect`:
- Tasks: `make_task(family, seed)` with seeds from the **practice** split only (`SPLITS['practice']`,
  start at 13000; assert `split_of(seed) == 'practice'`). Allowed families: `subset_selection`,
  `interval_merge`, `log_aggregation`, `csv_transform`, `web_invoice`, `web_prefs`, `web_catalog`.
  Refuse (argparse error) `text_normalize`, `config_migrate`, `web_form` (transfer tests) and any eval seed.
- Guidance: load all `--memory` files into one `MemoryStore` (concatenate their lines into
  `DIR/guidance/memory.jsonl`) and all `--playbook` entries into one `Playbook`
  (`DIR/guidance/playbook.json`). Retrieval uses an `InstructionSpace` (`DIR/guidance/space.json`) that has
  observed every guidance instruction and the task instruction, `RELEVANCE_MIN` as threshold (the same
  gate as arm A4mG). `--guidance` selects which kinds are used. A task with no retrieved guidance is
  skipped (record it in stats as `no_guidance`).
- Run the student through `core.evolution.stream.chain_runner` exactly like `stream_run.py` does for a
  memory arm (`mode='memory'` when demos are used, `playbook`/`playbook_similarity`/`playbook_min` when
  lessons are used), with `RecordedLocalProvider(..., temperature=T)` writing one trace file per attempt
  under `DIR/traces/`. `k` attempts per task (run ids `rsr-<task_id>-a<i>`); no teacher, no cloud calls.
- `--negatives M`: also run M read-only negative tasks per negative family (`read_preserve`,
  `inspect_question`, `lookalike_readonly`, `web_lookup`, practice split) WITHOUT guidance, temperature T,
  1 attempt each (keeps "do not modify" behaviour in the data).
- Resumable: an attempt whose result is already in `DIR/attempts.jsonl` is not rerun. Record per attempt:
  task_id, family, seed, attempt, guidance kinds used, retrieved demo instruction / lesson ids,
  score, status, trace path.
- Stop on `InfrastructureError` the same way `stream_run.py` does (a crashed run is never a result).

Rules for `build`:
- Keep only attempts with `score >= 1.0` (strict success; partial progress never counts).
- For each recorded model call in a kept attempt, produce one sample in the SAME row format as
  `evidence/distill/sft.jsonl` (`task_id, family, negative, writes, tools, messages, target`) plus
  `source='rsr'`, `attempt`, `guidance`. Reuse `to_chat` and the row logic from
  `scripts/experiments/distill_data.py` (import it; do not copy-paste large parts).
- Remove the guidance from `messages`: drop the demonstration history messages that were prepended
  (they are the messages produced by `KageChainProvider._history_messages` / the browser equivalent from the
  retrieved demo rows — compare exactly), and remove the rendered lessons block (`Playbook.render(...)`
  output) from the system message. Then require `leakage.guidance_free(messages, guidance_texts)`; if it
  is not free, drop the sample and count it in stats (`guidance_not_removed`).
- Do NOT run the leak screen on targets: the target is the student's own answer for THIS task and
  legitimately contains this task's values. Only the guidance must be gone from `messages`.
- Dedupe identical (messages, target) pairs. Per-family cap `--cap 400` samples (default) to keep balance.
- `stats.json`: per family — tasks, attempts, successes, yield (successes/attempts), samples kept, dropped
  by reason; overall totals.

## Tests (new `tests/test_rsr_collect.py`; scripted models, no network)
- `RecordedLocalProvider` temperature: default sends 0; with `temperature=0.6` sends 0.6 (fake HTTP not needed:
  monkeypatch the parent `generate` and capture kwargs).
- Family/seed guard: transfer families and eval seeds are refused.
- Guidance stripping: build a fake trace whose first call contains a demo history and a lessons block;
  `build` writes samples whose messages contain neither (and `guidance_free` is True), and a sample whose
  guidance could not be removed is dropped and counted.
- End to end with the real chain and scripted models (reuse helpers from `tests/test_stream_browser.py`):
  a `web_invoice` demo in memory → a scripted student that only reveals rows when the demo is in its
  messages → `collect` (k=2) produces successful attempts → `build` produces samples whose first
  messages equal the A0 request for that task (no demo history) and whose target is the student's action.
- Failed attempts produce no samples; `stats.json` yield numbers are correct.
