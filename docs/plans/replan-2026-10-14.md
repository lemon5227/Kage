# 计划审查与修正：从“单事件验收门”转向“学习曲线 + 对照”

2026-10-14，审查者：Claude（Cowork）。基线 `bea384d`（main 与 `codex/c2-learning-loop` 同一 HEAD）。
本文件审查 GPT/Codex 编写的 roadmap（G1–G4）及其 G1/G2 实践，并给出修正计划。修正后的执行入口已写回根目录 `roadmap.md`；旧版原文存档于 `docs/plans/roadmap-g1-g4-archived-2026-10-13.md`。

## 0. 我们的目的（用于判断一切工作是否值得做）

核心：一个能执行电脑任务、从失败与示范中学习、形成可复用能力并改进自身的 Agent；本地小模型执行，必要时云教师/人类教学。
用途：大厂面试展示与可能的博士申请。因此最终需要的产出是：

1. **一张可复核的“成长曲线”**：随任务流推进，同预算下新任务成功率上升、教师求助下降、旧能力不退化；
2. **一张消融/对照表**：相对原学生、等预算重试、轨迹记忆、简单固定策略，学习机制到底多出多少；
3. **一个能现场演示的闭环**：失败 → 教学/生成 → 验证 → 新变体上自动复用；
4. **一份 4–8 页技术报告**，可对应到 Voyager / ExpeL / AWM / ADAS / Gödel Agent / Darwin Gödel Machine / SICA 等工作给出定位。

## 1. 先肯定：已有实践里应保留的部分

- 证据纪律好：冻结协议、保留负结果、隐藏评分不进教师、validation/test 分离、不重跑救分。这在面试/申请里是加分项。
- 基础设施可复用：`EvolutionRunner`/`Evaluator`/`Promoter`/`Journal`/`BudgetTracker`、Docker 技能沙箱、不可变 bundle + digest、active/回退/幂等（`RecoveryLoop`）。
- 2026-10-09 的纠偏（停 TextEdit/AX 诊断链、回到 Agent 本体）方向正确。

## 2. 主要问题

### 2.1 度量单位错了：用“单个事件的证据链”代替“成长”

G1/G2/G3 的验收都是 n=1 的事件：G1 是 父0/子1、重启应用 1/1；G2 基线每项各跑一次。整个项目迄今关于“学习收益”的最强证据是一个任务族、3 次重复（C4.4 技能 3/3 vs 原学生 0/3）。
这种证据能说明“管线接通了”，不能回答“Agent 是否在成长”。G3 才计划做对照，而且只有 36 次；G4 之前没有任何学习曲线。照此推进，几个月后仍拿不出一张能展示的成长图。

### 2.2 演化对象过窄，且接口本身有缺陷

`core/agentic_loop.py:604`：恢复策略在 `not tool_calls and tool_calls_executed` 时触发——**即模型执行过任意工具后、准备正常结束的那一刻**，每任务一次；动作只能是 `stop` 或 `switch_tool → skill_call`。

后果：
- 它不是“失败恢复”，而是“对每次结束的强制改写钩子”。G1 学到的策略（读到文件 → 调用 knapsack 技能）会劫持所有读过文件的任务。
- 因此 G2 基线里“读取保留任务被改坏”是**钩子设计的必然结果**，不是新发现的能力缺口。G2 计划用一次“学习”去补宿主接口的缺陷，学到的大概率是一条 `if '保持不变' in goal` 式关键词规则。
- 可演化面只有“选不选这个唯一技能”，即使成功也很难构成有说服力的“自修改”。

### 2.3 G2 的验证集与来源同模板，容易产生虚假泛化

来源 `pricing.py` 与验证 `labels.py`、`events.log` 的指令都是“Read X … Leave X unchanged”同一句式。教师看到来源轨迹后写一个句式匹配即可通过全部验证，晋级会被记为“学会适用性”，实际是词面捷径。

### 2.4 最关键的对照被推迟

“演化出的策略是否优于一条人写的简单规则”是整个 L2 方向成立与否的问题，roadmap 却放到 G3，而且自己也承认“若简单策略相当或更好，优先保留简单策略”。在当前接口下，简单规则几乎必然相当。这个问题应在投入之前回答，而不是在三道门之后。

### 2.5 预算把实验压成了统计上无效的规模

教师授权总共 6 请求 / $0.03，G1 实际只用了 $0.0017；G2 学习包再限 3 请求 / $0.02。按 DeepSeek 价格，一次教师调用约 $0.002，**$10 就能支撑数千次调用**。同时，开发侧（Codex 写代码、写文档、审查）的花费和时间远高于这个数量级。省掉了最便宜的资源（云教师调用），却浪费了最贵的资源（你的时间和开发模型 token），还导致所有实验只能 n=1。

### 2.6 过程开销远大于研究产出

2026-09-28 以来 16 天：183 次提交，文档新增约 1.09 万行、测试新增约 1.18 万行、代码新增约 1.56 万行；148 个测试文件。每个微步骤都有计划、报告、审计 json、ledger 与 roadmap 改写。roadmap 入口里大量篇幅是“授权已用 2 次、估价 $0.0017454、不重复索要同一 key、新 root 不得重置预算”这类账务条款，下一位模型很难读出“现在要做什么、为什么”。严谨本身没有错，但它已经变成主要产出。

### 2.7 “学到的东西”其实都是教师一次写出的

knapsack 技能和恢复源码都是 DeepSeek 单次生成；本地 4B 学生不参与学习，只是执行。C4.4 的 3/3 实质是“把一族题的解法缓存成技能，再迁移到改名变体”。这是合理的起点，但要支撑“自演化”叙事，至少需要：多族、多技能、技能被正确选择/拒用、随经验累积的曲线，以及与轨迹记忆（ExpeL/AWM 式）的对照。

### 2.8 证据保存风险

G1/G2 的唯一原始证据在被 Git 忽略的 `~/.codex/worktrees/c2-learning-loop/Kage/artifacts/`。worktree 被清理或磁盘问题会导致报告无法复核。

## 3. 修正后的计划（P0–P5）

原则：**一个基准、一条主实验、对照从第一天就在**。保留 G1 机制作为基础设施，不再按“一个事件一道门”推进。

### P0 清理与止损（1–2 天）

1. 备份原始证据：将活动 worktree 的 `artifacts/` 打包到 Git 之外的第二位置（外置盘/云盘），记录 sha256。
2. G2 适用性学习包**不作为主线执行**。基线结论保留为一个有价值的负发现：“无条件触发的已学模块会误用并造成副作用”。其关注点（适用性/误用）并入 P1 基准的负例指标，在多句式、多族上统计测量。
3. 修复恢复钩子接口（开发修复，明确记为宿主改动，对所有臂一致）：触发原因区分 `finish_attempt` 与真正的失败信号（工具错误、无进展、模型自报无法完成）；向策略提供模型最终文本与本任务已写文件列表；默认策略为接受结束。G1 的子策略在新接口下重新作为一个候选参与对照，不改写历史成绩。
4. 精简文档纪律（见 roadmap §6）。

### P1 基准：Kage-Stream v1（约 1 周）

复用现有 runner/Evaluator（`python_function`、`read_preserve`）与 Docker，不新建评分系统。

- **6 个可程序化生成的文件/代码任务族**，每族有实例生成器（函数名/文件名/字段名/数值/边界情况随机，指令至少 3 种句式）：
  F1 子集选择（已有 knapsack，兼作旧能力回归）、F2 区间合并/排期、F3 日志解析聚合、F4 CSV 清洗变换、F5 文本规范化、F6 配置格式迁移。
- **负例约 20%**：只读/保持不变、无相关技能、问答型；指标是误用率（任何不适用的 skill_call 或文件改动）。
- 划分：F1–F4 进入学习流；F5–F6 只出现在评测中（跨族迁移与负迁移）；评测实例与流实例用不同 seed 生成，冻结哈希。
- 难度标定：先用原学生跑每族 10 个实例，目标原学生成功率 10–50%；全 0 或全满的族调整参数后再冻结（标定数据不进入正式评测）。
- 产出：`eval/stream-v1/` 生成器 + 冻结实例清单；`scripts/experiments/stream_run.py`（顺序执行、任务间学习、检查点评测）；`scripts/experiments/stream_report.py` 从原始结果自动生成表格与曲线。

### P2 主实验 E-Stream-1：L0/L1 是否带来成长（1–2 周，主要是机器时间）

| 臂 | 内容 | 作用 |
|---|---|---|
| A0 原学生 | 4B 本地，无记忆无技能 | 下限 |
| A1 等预算重试 | 同总请求/步数上限内自我重试 | 排除“只是多花预算” |
| A2 失败即教师 | 每次失败让教师接管，不保存任何东西 | 成本参照与上限 |
| A3 L0 轨迹记忆 | 验证过的成功轨迹存档、检索 top-k 注入 | ExpeL/AWM 式对照 |
| A4 L1 技能库 | 失败→教师解→提取参数化技能→验证→入库；学生检索/调用 | 主假设 |

- 学习流 60 个任务（F1–F4 + 负例）；在流的第 0/30/60 个任务处冻结快照，用同一套 48 实例评测集（族内 24、跨族 12、负例 12）。
- 2 个流顺序 seed 起步；结果清楚再加第 3 个。
- 指标：族内/跨族成功率（Wilson 95% CI，按实例配对，McNemar 检验臂间差异）、负例误用率、每解决一题的教师调用与费用随流下降情况、F1 旧能力保留、耗时与 token。
- 量级估计：每次运行约 30–75 秒，A3/A4 每 seed 约 60+3×48 次，合计约 900 次运行，约 15 小时本机时间，可分两晚跑完。教师调用估计数百次，约 $1–3。
- 主假设 H1：A4 在第 60 个任务处的族内成功率显著高于 A0/A1/A3，且教师调用随流下降；H2：负例误用率不高于 A0 + 5 个百分点；H3：F1 不退化。任何假设不成立都照实报告——负结果同样可以写进报告。

### P3 L2：在技能库之上演化“如何用经验”（1–2 周）

只有 P2 中 A4 有收益时才进入。演化对象：技能选择/适用性/恢复策略（P0 修复后的接口），候选由教师基于流中真实失败生成，Promoter 在独立 validation 上晋级，active/回退沿用 G1 机制。
必须对照：A4 + 人写简单固定策略。若演化版不优于简单策略，结论就是“L2 在此设定下不必要”，并停止扩展。
可选：学生（本地 4B）自己提候选 vs 教师提候选，区分“自修改”与“教师代写”。

### P4 条件扩展（选一）

- L3 蒸馏：P2/P3 产生的已验证轨迹 ≥ 300 条且去重后，做 4B LoRA（Colab/租用 GPU），评测时关闭检索与云。
- 浏览器：把同一 stream harness 接到已有浏览器任务族（C2/C4.5），检验机制是否跨环境成立。

### P5 产出（约 1 周）

技术报告（方法、基准、曲线、消融、负结果、成本）；README 换成成长曲线与对照表；3 分钟演示视频（失败→教学→新变体自动复用→负例不误用）。

## 5. 对外可说与不可说（不变）

可说：受控文件/代码环境中，教师辅助技能生成、单族迁移（3/3 vs 0/3）、恢复源码生成→验证→持久采用的闭环工程，以及完整负结果。
