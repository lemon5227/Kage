# 巩固环：把“带指导的成功”变成权重（借鉴 Terminal-RSI，2026-10-18）

来源：Yang et al., *Terminal-RSI: Recursive Self-Improving Terminal Agents via Recursive Self-Rewrite and Policy-Refine*（腾讯 Hy Frontier 等，arXiv:2610.22192，2026-10-15）。读了方法与奖励部分（§1–2.2）和结果摘要。

## 1. 论文要点与取舍

| 论文组件 | 做法 | Kage 取舍 |
|---|---|---|
| **RSR 递归自重写** | 已验证轨迹（可来自更强的配置）→ 规划器写 **runbook** → 只看公开任务与 runbook 的**泄漏审查** → 目标模型带 runbook **重新执行** → 通过验证与泄漏筛查的轨迹**删掉 runbook** 后做 SFT。单这一步四套基准均值 20.7% → 34.3% | **采用**，作为新的巩固环和 B 的主数据来源 |
| **RPR 递归策略精炼** | PPO + 继承的价值网络（critic），TB-GAE 按交互轮次而非 token 衰减 | **不采用**（T4 + 4B 做不了 PPO/critic）；用“多次采样 + 只留验证通过的”（拒绝采样 / expert iteration）代替 |
| **FDR / SPR 奖励** | 部分进度按任务族归一化；部分得分始终低于严格成功（原奖励下失败轨迹拿走 50% 奖励） | **只取原则**：训练只用严格成功；部分进度（通过的用例比例、记录字段匹配数）只用于课程排序（差一点就成功的题优先练）和报告，永不当作成功 |
| **递归** | RSR-1 → RPR-1 → RSR-2 → RPR-2，每轮从上一轮保留的模型出发 | **采用**：LoRA-1 学生再跑流 → 新失败 → 新 runbook → RSR-2 → LoRA-2 |
| 评测纪律 | Mean@3、报告被丢弃的分支、区分“完成率 / 塑形奖励 / 检查覆盖” | 已在做（A0 三次重复、负结果入报告），保持 |

为什么适合 Kage：C2 的结论是“学生检索到了示范但很少照做”（检索可靠，采纳是瓶颈）。RSR 的做法正好绕开采纳问题——把“带指导时做成功的过程”训练进权重，评测时不再需要上下文里的指导。而且训练数据是学生自己生成、自己格式的轨迹，比把教师示范硬转成学生格式（现有 `distill_data.py`）更贴合分布。

## 2. 对应关系

```
论文            Kage
更强的配置      云教师示范（TeacherCache，已付费缓存）/ 用户 👍 的真实任务
runbook         C3 经验规则（lessons）+ 标签级示范（memory）
泄漏审查        新增：确定性筛查（R1），规则/runbook 里不得出现评分数据或实例取值
重新执行        学生在 practice 划分的新变体上带 runbook 执行，k 次采样（温度 0.6）
验证+筛查       原有独立检查器（文件用例 / 浏览器后台记录）+ 泄漏筛查
删除 runbook    训练样本的系统提示与 A0 完全相同（runbook 不进样本）
SFT             现有 lora_train.py（T4 fp16 + LoRA）
递归            LoRA-k 学生 → 新失败 → 新 runbook → RSR-(k+1)
```

## 3. 任务（替代原 B 的数据路径；C3 结果决定 R2 用哪种 runbook）

- **R1 泄漏筛查**（小，交给 DeepSeek 执行器）：规则/runbook 进入 playbook 或训练前，拒绝含有评分数据（期望记录、隐藏用例的值）或当前实例取值（指令里的引号字符串、数字、人名/文件名）的条目；训练样本删掉指导后再检查一遍不含指导文本。单测覆盖。
- **R2 带指导的新鲜执行采集**（`rsr_collect.py` + Kaggle 阶段）：practice 划分（13000–17000）新变体；可学族 F1–F4 + web_invoice/web_prefs/web_catalog；**F5/F6 与 web_form 永不进训练**（留作迁移测试），eval 划分永不使用。每题 k=4 次、温度 0.6；保留严格成功且通过泄漏筛查的轨迹，删去 runbook 写成 SFT 行（与 `distill_data.py` 同格式）；每族上限保持平衡；按“部分进度高但失败”的题优先补采。目标约 2000 条。教师花费只有 runbook（从已缓存示范生成，每簇几次调用，约 $0.05）。
- **R3 LoRA-1 与评测**：在 R2 数据上训 LoRA；**不带任何指导**在冻结的 stream-v1 与 stream-web-v1 评测集上评（A0×3 同环境重复给出波动范围）；验收：族内超出 A0 重复范围、负例误用不增加、F5/F6/web_form 迁移如实报告、通用能力抽查不退步；不达标就回退（不启用适配器）。
- **R4 递归**：LoRA-1 学生跑学习流（A4mGL），新失败 → 新 runbook → RSR-2 → LoRA-2，与 LoRA-1 对比。

## 4. 风险与停止条件

- C3 若显示带规则的新鲜执行成功率几乎不高于 A0，R2 产出率会很低：先加大 k，再考虑只用示范 + 规则的组合；仍不足就先停在 R2，报告产出率。
- 训练数据过于单一（同族模板）会让 LoRA 只记模板：每族上限、模板多样性和 web_form/F5/F6 迁移测试用来发现这一点。
- Kaggle GPU 时间是主要成本；每个阶段先做小规模冒烟（约 200 条）再放大。
