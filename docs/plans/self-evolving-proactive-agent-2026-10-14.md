# 自进化 · 自动演化 · 主动交互 Agent：目标定义与实现方案

2026-10-14。本文件定义三个目标词的**可测含义**，给出系统架构、与现有代码的对应、实验设计、$1 预算分配和紧缩时间表。执行入口仍是根目录 `roadmap.md`；问题诊断见 [计划审查](replan-2026-10-14.md)。

## 1. 三个目标的操作定义（不满足定义就不能声称）

| 目标 | 定义 | 用什么证明 | 不算数的情况 |
|---|---|---|---|
| **自进化** | Agent 根据自身经验改变自己的能力存储：L1 技能库、L2 策略（求教/技能选用/恢复）。改动经验证后自动生效，无需开发者介入 | 任务流上的成长曲线：同预算新题成功率↑、教师调用/题↓、旧能力不退 | 开发者修代码；一次性重放示范；教师替做的任务计为学生成功 |
| **自动演化** | 学什么、何时学、何时练习、何时淘汰由系统自己决定：任务流中在线学习 + 空闲时后台“练习/整理”（sleep-time） | 后台演化前后同一冻结评测集对比；目标选择由能力模型自动产生的日志 | 人指定“这次学 recovery”“这次练 knapsack” |
| **主动交互** | Agent 主动发起交互：①**求教**——自评没把握时主动请教师或用户演示；②**汇报与确认**——学会新能力后主动告诉用户证据并请求启用（高风险时）；③**提议**——发现用户重复做某类事时主动提出做成技能 | ① 求教的精准率/召回率（问了的是否本会失败）与“每多解一题的教师成本”；② 每次采用都有用户可读的汇报与确认记录；③ 演示中的提议样例 | 只在报错后才回退云端（现有 hybrid fallback）；定时推送无关通知 |

三者是**同一个闭环**，核心枢纽是**能力自评（competence model）**：Agent 知道自己哪里不行 → 主动求教（主动交互）→ 学成技能并验证（自进化）→ 空闲时按薄弱点练习、整理技能库（自动演化）→ 汇报给用户（主动交互）。这也是对外的研究定位：

> **Competence-aware proactive continual learning for small local agents**：本地 4B 模型 + 廉价云教师，在 16GB 设备上，靠自评驱动“何时求教、学什么、练什么”，用远低于“每次都叫教师”的成本获得持续成长。

与相关工作的区别：Voyager/ExpeL/AWM 侧重技能/经验库但默认强模型、无主动求教；ADAS/Gödel Agent/DGM/SICA 侧重改代码但成本高、无与用户的交互。Kage 的组合点是**小模型 + 自评驱动求教 + 后台自练 + 低成本**。

## 2. 系统架构：三个时间尺度的环 + 一个交互层

```
                 ┌──────────────────── 交互层（主动）─────────────────────┐
                 │ 求教请求 / 学习汇报 / 启用确认 / 重复任务提议           │
                 │ 复用 heartbeat 通知队列 + Launcher/Live2D 气泡          │
                 └───▲───────────────▲──────────────────────▲─────────────┘
                     │               │                      │
 ① 执行环（秒）       │ 求教           │ 汇报                  │ 提议
 观察→行动→自检 ──→ 求教门 ───┐        │                      │
   AgenticLoop        (能力模型)│       │                      │
                               ▼       │                      │
 ② 学习环（每任务，分钟）               │                      │
 失败/求教 → 教师或用户示范 → 提取参数化技能 → 沙箱自测 → 入库(候选)
   TeacherTakeover / demonstration     mutator/skills      Promoter
                               │
                               ▼
 ③ 演化环（空闲/夜间，后台）
 按能力模型选薄弱族 → 生成变体自练 → 修技能 / 合并去重 / 淘汰低效技能
 → 演化 L2 策略（求教阈值、技能选用、恢复）→ validation 晋级 → active/回退
   BackgroundWorker + heartbeat 调度；search.py / RecoveryLoop 的 active、回退、幂等
```

### 2.1 能力模型 `core/evolution/competence.py`（新增，约 150 行）
- 输入：Journal 中每个任务族/技能的历史结果（成功、失败、教师介入、用户反馈）。
- 输出：每族的成功率估计与置信度（Beta 后验即可）、每技能的调用次数/成功率/最近使用。
- 用途：求教门的决策；演化环选择练习目标；技能淘汰；汇报内容。
- 任务族识别：先用基准自带的 family 标签；P3 再换成“技能检索命中 + 指令嵌入近邻”的自动归族，测试自动归族的准确率。

### 2.2 求教门（执行环）
- 位置：P0 修复后的钩子。动作空间从 `stop / switch_tool` 扩展为 `stop / switch_tool / request_help`。
- 触发：任务开始前（能力模型给出的成功概率低于阈值）或执行中（工具错误、无进展、自检失败）。
- 运行时**不能看外部 checker**；可用的信号只有自检（运行自己写的测试、读回文件）、工具错误和能力模型。外部 checker 只用于评分；任务结束后的对/错可以当作“用户反馈”使用（等价于用户说“不对”），这是合法的学习信号。
- 求教对象：DeepSeek（默认，有费用上限）或用户（演示模式下，通过交互层弹出“这个我不会，能演示一次吗？”，复用浏览器示范录制）。

### 2.3 学习环
- 复用 C4 路径：`TeacherTakeoverProvider` 得到验证过的轨迹 → `mutator` 提取参数化技能 → Docker 沙箱运行**教师生成的测试 + 原任务 checker 反馈** → 候选入库。
- 新技能先处于“试用”状态：在下一个同族任务上真实调用成功后转为“已启用”；失败两次则退回修复队列。这让采用由真实使用决定，而不是一次验证。
- L0 轨迹也同时入档（ExperienceArchive），供 A3 对照与技能修复使用。

### 2.4 演化环（自动演化的主体）
在空闲时由 BackgroundWorker 执行，按预算排队，每轮：
1. **选目标**：能力模型中“出现频率 × (1 − 成功率)”最高的族。
2. **自练**：族生成器（基准内）产生 k 个新变体，本地学生带技能库执行；全部本地，0 云费。
3. **修/合/汰**：自练失败 → 教师修技能（skill_mutator），validation 晋级；功能重复的技能合并；30 次未被使用或成功率低于原学生的技能停用。
4. **L2 策略演化**（P3 后半）：对求教阈值和技能选用/适用性策略生成候选，在 validation 上与 active 比较，晋级/回退沿用 RecoveryLoop 机制。必须和人写固定规则对照。
5. **汇报**：本轮学会/修好/停用了什么，附验证数字，进入交互层队列。

### 2.5 交互层
- 复用 `core/heartbeat.py` 的通知队列（用户活跃时暂存，空闲后发送）与 Launcher/Live2D 显示。
- 三类消息：求教请求（可拒绝，拒绝即走教师或放弃）、学习汇报（“学会了日志汇总，3 个新题验证通过，已启用”）、启用确认（会写文件/有副作用的技能首次启用前询问）。
- 提议（③）：记录用户发起的任务；同一族出现 ≥3 次且尚无技能时提议“要不要我学会它”。P3 只做演示级实现，不作为主指标。

## 3. 实验设计（全部在 Kage-Stream v1 上）

| 臂 | 学习 | 何时求教 | 后台演化 | 阶段 |
|---|---|---|---|---|
| A0 原学生 | 无 | 从不 | 无 | P2 |
| A1 等预算重试 | 无 | 从不 | 无 | P2 |
| A3 L0 轨迹记忆 | 轨迹检索 | 任务失败反馈后 | 无 | P2 |
| A4 L1 技能库 | 技能提取 | 任务失败反馈后（被动） | 无 | P2 |
| A5 A4 + 主动求教 | 技能提取 | 能力模型/自检触发（主动） | 无 | P3 |
| A6 A5 + 后台演化 | 技能 + 自练 + 修/合/汰 + L2 | 主动 | 有 | P3 |
| A6-fixed | 同 A6，L2 换成人写固定规则 | 主动 | 有（无 L2） | P3 |

- 流：60 任务（F1–F4 + 负例），2 个顺序 seed；检查点 0/30/60，每个检查点评测 48 个冻结实例（族内 24 / 跨族 F5–F6 12 / 负例 12）。
- 指标：族内/跨族成功率（Wilson CI、配对 McNemar）、负例误用率、**每题教师调用与累计费用**、求教精准率/召回率、F1 旧能力保留、后台演化前后差值。
- 假设：
  - **H1 自进化**：A4@60 > A0、A1、A3。
  - **H2 主动交互**：A5 的成功率不低于 A4，教师调用更少；或调用相同、成功率更高。
  - **H3 自动演化**：A6 > A5，且 A6 > A6-fixed 才能说 L2 有用；否则报告“自练/整理有用，L2 不必要”。
  - **H4 安全**：负例误用率 ≤ A0 + 5pp，F1 不退化。
- 去掉独立的“失败即教师”臂：教师上限与成本直接从 A4/A5 的求教事件中统计，节省约一半云费。

## 4. $1 预算分配（DeepSeek，单次约 $0.002）

| 用途 | 估计调用 | 估计费用 |
|---|---|---|
| 教师示范（**按任务实例缓存**：从干净初始状态解题，跨臂、跨 seed 复用） | ≤60 实例 × ~3 = 180 | ~$0.35 |
| 技能提取与测试生成 | ~25 技能 × 2 = 50 | ~$0.10 |
| 后台演化：技能修复 + L2 候选 | ~40 | ~$0.08 |
| 演示与汇报文本 | ~20 | ~$0.04 |
| **预留** | — | ~$0.40 |
| **硬上限** | — | **$1.00**，BudgetTracker 先预留后执行，超限即停 |

关键省钱设计：教师从干净状态解题并按实例缓存，所以 A3/A4/A5/A6 和两个 seed 共享同一份教师示范，云费不随臂数增加。练习、评测和学生执行全部在本地完成。
