## 浏览器闭环之后

默认顺序：**C2.1-R1状态 → R2技能发现 → R3步数/结束 → 新留出 → C5.0最小入口 → C4.5-DOM人类示范 → C1.2 AX → C4.5-AX → C2.2跨应用任务**。可靠性先做固定小诊断，不无限延期入口；随后完善C5/E5与E6。

B2.2发现两条待验证瓶颈：compact省略false可能误导勾选状态解释、提供技能后模型仍不发现/调用。R1在dev用真实云执行者从干净页面做6次状态投影对照；R2分别对照搜索和最小技能预览，不同时改多个变量；旧test不用来调技能。C5.0只提供显式实验模式与可信完成/失败/unknown，不把未晋级候选设默认。

研究线 **E2.1完整档案 → E3.1更多自修改 → E4路由** 在B2.2后即具备独立领取条件，可与电脑扩展交替，不能无限延后。单人资源默认串行，每次仅一个包；同目录不同时改同一执行链，模型推理不与重测试争抢资源。

| 条件支线 | 何时领取 | 限制 |
|---|---|---|
| C7后续 | 长轨迹、跨页事实或动作开销有实际证据 | 不把所有旧DOM丢掉称通用记忆；逐机制对照 |
| C6 | DOM/AX确实覆盖不了的任务 | 定位模型只负责找目标；量化/坐标/整任务分别验收 |
| C8 | 同权重可用且推理是瓶颈 | 先测缓存/全任务，无重复收益不换默认服务 |
| C3 | 有明确决策瓶颈、可用API | 可选对照，不先训Jev |
| E7 | 去重且多样的验证轨迹、隔离留出、GPU/导出可行 | 先小批训练/导出试跑，权重收益与技能收益分开 |
| E6 | 主要方法已可运行 | 预注册划分从现在就做，完整研究验收在数据完成后 |

## 接口归属与完成标准

C1执行观察/动作；C2独立完成检查与评测；C4示范接管/学习入口；E2证据档案；E1候选/执行/晋级；E3真实模块源码修改；E4修改目标选择；E7权重训练。共用runner/journal/budget/Promoter，不新建第二套评分。

状态分为工程完成、真实模型pilot、独立迁移、研究验收、主链集成五个层级；能运行一次不自动满足后四项。结果可以是未提升；实验完成不等于能力提升完成。每包报告实际执行者、原始分母、失败、版本、预算、代码及报告提交；历史结果不回写。原始artifacts暂只在活动worktree，交接前核对路径/hash，迁移须另记映射和索引重建。
