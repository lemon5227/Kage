## 架构与资源决策

现有执行主链：PromptBuilder → ModelProvider/Broker → AgenticLoop → ToolExecutor/ToolRegistry → 工具证据 → 下一步。E1在这条链上绑定候选私有技能，独立runner评估实际输出，比较父子候选并记录晋级。

下一阶段目标链：用户目标 → 当前子目标 → DOM/AX/OCR/必要截图观察 → 当前动作候选 → 本地/云决策 → 执行与重新观察 → 独立完成检查 → 轨迹/失败经验 → 可执行技能 → 留出复验与晋级。新增观察器、决策接口、人类示范和通用GUI评测尚属规划。

- 本机负责环境观察和执行；小模型处理可完成的步骤，复杂规划与恢复按预算交给廉价云模型。真实能力与路由阈值需要实测。
- 自行训练Jev暂缓；Jev API为可选后端，不阻塞主线。SGLang先吸收候选分数与缓存思想，不部署CUDA服务。
- LocateAnything-3B保留为视觉定位实验，不能当完整规划模型；SoL-Pi吸收动作合并、观察打包和证据保留的上下文机制。
- oMLX保留为后续通用引擎对照，先验证同权重、工具协议与内存；Husky不进入当前实施队列。
- Colab已验证T4可用，登录时compute units为0；资源不保证随时可得。微调不作为当前前置条件。云教师纠正→技能迁移→批量适配器训练的分阶段建议见[学习闭环设计](plans/cloud-teacher-local-student-2026-10-01.md)，尚未实施。

## 模型交接与记录规则

后续模型先读本页，再只读领取任务的设计段落及最新相关报告，并检查当前Git状态与代码。需要追溯时才打开旧报告；不要求每次把所有历史加入上下文。文档拆分本身不会自动控制程序的检索或上下文注入，程序接入时也应按任务选择相关材料。

每个任务单独提交，修复与无关功能分开。报告包含：问题、基线、复现、根因、实际修改、失败尝试、版本/配置、验证命令与结果、真实成功及失败、限制和下一步。原始轨迹置于artifacts，报告说明存放位置与是否纳入Git；敏感凭据不写入报告。

[实验报告索引](experiments/README.md)是全部证据入口。总规划只更新状态与链接，避免增长为逐轮聊天日志。
